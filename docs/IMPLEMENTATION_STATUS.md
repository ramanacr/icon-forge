# Implementation status

Phase 0 is in progress. At the user's direction, Phase 1 independent work has started before the formal S-01 through S-06 gate closes. The v4 engineering package remains the design authority; the Phase 1 exit is not yet met.

## Phase 1 kickoff

- A pure SVG profile compiler now creates sorted per-icon SVG artifacts and a deterministic hash manifest from a validated project and saved SVG export profile. The Node CLI reads `.iconproj`, compiles into a new output directory, and supports `--check` against existing output. Unit tests compare CLI output to the pure compiler, and Chromium checks artifact and manifest byte parity with Node.
- The framework-independent editor core now holds transform preview frames outside the project journal, validates the selected nodes at gesture start, and commits one `selection.transform` command at pointer-up. Identity and cancelled gestures write nothing; stale revisions reject a commit. Undo and replay tests cover a 100-frame preview.
- The editor core now builds native SVG DOM directly from the canonical scene, including primitives, paths, groups, variants and parameterized components. Selectable model nodes carry their IDs; component-owned nodes remain inside the instance wrapper. A Chromium fixture compares its pixels with the SVG export and checks that accessibility text cannot create script elements.
- A separate ephemeral selection model orders IDs by scene order, rejects missing/duplicate/ancestor-overlapping targets, and reconciles deletions without journaling. Variant replacement geometry renders but has no base-scene selection ID until variant editing commands exist.
- A pure geometry query now computes bounds for visible scene nodes, nested affine transforms, quadratic and cubic extrema, ellipses, variants and component bindings. It leaves the project unchanged and excludes stroke expansion.
- Pure grid helpers now provide bounded overlay guide positions and independent-axis point snapping with a caller-supplied screen tolerance converted to icon units. They keep preview coordinates out of the project journal.
- The native SVG renderer now accepts a revision-bound transform preview and composes it with an existing node transform. Chromium verifies that the preview leaves project and journal unchanged and matches the one-command committed rendering.
- An Angular 22 browser shell now wires project and icon creation, rectangle placement, renderer selection, one-command transform gestures, undo/redo, revision-checked IndexedDB journal saves, Web Lock single-writer mode, journal replay on reload, and SVG profile export. A Chromium E2E test covers create → edit → undo/redo → downloaded SVG → reload under the production CSP. The Phase 0 conformance and Windows picker items below remain open.
- The editor now exposes ellipse and line primitives, live pointer drag preview with whole-unit grid snapping, and one-command commit on release. Grid and safe-area overlays stay out of exported SVG. A layer list supports multi-selection, grouping and ungrouping. The browser offers explicit read-only takeover and corrupt-tail recovery; lock ownership changes update both tabs. Six Chromium E2E cases cover these flows, including byte-for-byte comparison of the downloaded SVG with Node compilation of the saved journal. The initial production shell is about 133 KB raw JavaScript and CSS; editor code loads on demand.
- The normative `node.update` command now accepts typed fill and stroke operations, rejects unsupported targets and duplicate operations, and records one reversible node patch. Its JSON Schema and standalone validator are regenerated. The editor uses it to switch a selected shape between filled and outlined forms; a seventh Chromium E2E case covers undo, redo and export.
- Focused layer buttons now accept arrow keys for one-unit moves through the same journalled transform gesture. The inspector accepts exact X/Y positions, fill color and stroke width, and disables ungrouping when a transformed group no longer meets the neutral-group contract. Browser E2E cases cover keyboard movement, numeric positioning, paint/stroke edits, export and undo.
- Repeated shape types receive distinct accessible layer names. A composite browser icon with rectangle, ellipse, line, color and grouping now exports byte-identically through the built Node CLI. Parity CI builds both the CLI and web app before running the browser cases. The M1 functional scope is demonstrated in Chromium; formal Phase 1 exit still depends on the open Phase 0 gates and deferred cross-engine verification.
- The editor uses semantic CSS tokens, accessible canvas grouping, visible focus, reduced-motion handling and 44 px touch targets. Phone-sized touch screens show an explicit preview-only state. Axe-core reports no WCAG 2.2 AA violations in the tested Chromium editor state. A manual assistive-technology audit, cross-engine accessibility checks and a broader representative icon corpus remain open. The full WCAG 2.2 AA audit is scheduled for Phase 8.
- Drag preview now updates selected SVG transforms in place while the journal remains unchanged until release. The layer sidebar scrolls independently so a 225-shape scene keeps the canvas visible. A Chromium E2E regression case checks stable scene DOM, snapped committed coordinates and synchronous pointer feedback p95 against the 60 fps budget with 10% tolerance; the measured local p95 was about 0.3 ms across 20 moves. This timing excludes browser paint and has not been verified on the reference laptop. Fifteen Chromium web E2E cases pass.

Environment-dependent blockers are tracked in [BLOCKERS.md](BLOCKERS.md).

## Implemented foundations

- pnpm 11 / Nx workspace with Node 24 and TypeScript 6.0. Tagged package dependencies are enforced by Nx ESLint in CI; a forbidden import probe was rejected.
- V1 project types, Draft 2020-12 JSON Schema generation, CSP-safe standalone validator, semantic checks (including variant replacement IDs and targets, and component parameter/argument types, ranges and field bindings), canonical serialization and half-even quantization.
- Pure ordered migration framework with final-schema validation and read-only opening of future-major project documents, including `.iconproj` containers. There is no historical production version to migrate yet.
- Pure project create/rename/design-system update, token upsert/remove, icon add/rename/remove/duplicate/updateMetadata, variant add/update/remove, component add/update/remove, node add/remove/reorder/group/ungroup, selection.transform and export-profile upsert/remove handlers with revision checks and reversible structural patches. Duplicate uses a caller-supplied ID map for owned nodes and variants, and derives a collision-free copy slug. Metadata updates cover tags, aliases, accessibility and font mapping; explicit `font: null` clears a mapping. Node removal handles multiple nodes in nested groups with stable inverse order and rejects parent-child overlap. Node reorder moves between sibling arrays with the destination index measured after removal, rejects moving into its own subtree and replays from bounded patches. Grouping creates a neutral group around selected siblings in scene order; ungrouping rejects groups whose properties or variant references would be lost. Selection transforms compose a prequantized matrix in parent coordinates and commit once for the selected nodes; overlapping parent/child selections are rejected. Patches address affected entries or fields to keep journals bounded; token and component removal check references.
- Application dispatcher with dry-run, idempotency, revisioned undo/redo, structural patches persisted in the SHA-256 checksummed journal, replay, corrupt-tail reporting and defensive state copies. Replay fixtures cover 1, 200 and 5,000 commands.
- IndexedDB repository adapter with atomic revision-checked journal append, snapshot compaction and corrupt-tail truncation; browser-tested reload, two-tab Web Lock takeover and read-only revision announcements in Chromium.
- Persistent-storage status request, quota-error classification, deterministic `.iconproj` ZIP with SHA-256 project and original hashes, and native-file/download save adapter. Chromium passes a 2,000-icon snapshot and archive round trip.
- Pure `export-svg` serializer with escaped accessibility text, canonical paint and path output, precision fallback for narrow closed segments, selected variant overrides and static or parameterized component expansion. Bindings apply to copied nodes and reject invalid geometry. Node/Chromium parity covers the original golden fixture, a component/variant fixture and a bound component fixture. Archive extraction enforces path, entry count and byte limits before decompression.
- CI checks for frozen installation, generated-schema drift, typecheck, unit tests and a three-browser Playwright parity fixture.
- Chromium performance harness checks 100-icon IndexedDB snapshot open, 500-icon validation, 100 simple SVG serializations and p95 single-icon apply/undo against documented budgets with the required 10% tolerance. CI runs the measurement separately from other browser tests to avoid competing CPU workloads; one parallel local run exceeded the apply budget at 66.1 ms p95 and the isolated rerun passed.

## Gates still open

- S-01: Node/Chromium parity passes for quantization, checksummed journal replay, one canonical SVG fixture and seven pinned JSON/SVG corpus fixtures (fixed rotations, non-uniform scale, preconverted cubic arc, half-even boundary, negative zero and 500-icon serialization). The 2,000-run numeric property checks pass. Firefox, WebKit and import-stage arc conversion remain pending. The CI job is configured to install all three browsers, but it has not run on a remote runner yet.
- S-02: Paper.js runs four rectangle Booleans plus coincident/touching cases in a DOM-free, canvas-free Chromium worker; inputs stay unchanged and the minified worker is below 120 KB gzip. `IGeometryEngine` converts output back to quantized canonical paths. Rectangle, cubic-circle/rectangle, 0.1-unit thin-overlap and nested-hole fixtures meet raster IoU ≥ 0.999 for all four operations against Canvas compositing. An intersection below coordinate quantum now returns `boolean.unsupported-geometry` instead of a zero-area canonical path, while a representable 0.001-unit intersection succeeds. The broader curved/pathological corpus, full diagnostics and other browsers remain pending, so the spike has not passed.
- S-03: Rust/WASM outline adapter handles canonical lines, quadratics and cubics; butt/round/square caps; miter/round/bevel joins; open and closed strokes; duplicate-stroke and fill/stroke union; evenodd hole winding; zero-length round dots; large coordinates with small features; degenerate-area info; and the dashed-stroke error. Sixteen native Rust fixtures and four TypeScript adapter fixtures pass. Chromium verifies Node byte-equivalent outlines under CSP, raster IoU ≥ 0.995 for all nine cap/join combinations plus closed, reversal, dot, overlap and fill-only evenodd-hole examples, and typical-icon p95 ≤ 15 ms. New curved-stroke raster fixtures expose a quadratic arch at IoU about 0.982 and a cubic inflection at about 0.986; they are tracked as [B-06](BLOCKERS.md) with strict expected-failure tests. The outline bundle plus WASM is about 134 KB gzip, below 250 KB. Font compiler integration, a wider pathological corpus and the deferred browser verification remain, so the gate has not passed.
- S-04: resvg WASM in a Chromium worker produces byte-identical PNGs to Node across nine fixed sizes from 16–512 px, with correct alpha for the fixture, a local 512 px render under 250 ms and a gzipped WASM below 1.5 MB. Three additional pinned image fixtures cover evenodd holes, a curved round-cap stroke and translucent overlap at 48 and 128 px. Other browsers and still wider image cases remain pending, so the gate has not passed.
- S-05: deterministic OTF/CFF fixtures have `.notdef`, space, fixed PUA cmap, empty glyphs, ligatures with input glyphs, family-name sanitization and duplicate-codepoint rejection. Explicit advance and left bearing values are checked against independent Fontkit bounds and the written `hmtx` entry. Chromium builds byte-identical font data to Node, `FontFace` shapes ligature text to the PUA glyph, and simple and nested-hole glyphs reach raster IoU ≥ 0.98. Pinned WOFF2 output is deterministic; Fontkit recovers matching glyph contours, PUA mapping and GSUB ligatures. Chromium produces byte-identical WOFF2, loads and rasterizes it under CSP, and builds 200 OTF+WOFF2 glyphs within 3 seconds. TTF/cu2qu remains conditional under ADR-023; broader metric/glyph cases and other browsers remain pending, so the gate has not passed.
- S-08: local Node/Chromium encoder checks pass: exact package version and lockfile integrity, recorded WASM SHA-256, deterministic WOFF2 bytes, independent Fontkit semantic round trip, CSP loading with `'wasm-unsafe-eval'` but no JavaScript `unsafe-eval`, and font compiler plus encoder WASM about 395 KB gzip (budget 700 KB). See [S08_WOFF2.md](S08_WOFF2.md).
- S-06: Chromium append/reload, stale-write rejection, compaction, corrupt-tail recovery, two-tab takeover, revision announcements, 2,000-icon save/load, forced quota, interrupted-tab atomicity, deterministic abort after an in-flight journal put and a real `.iconproj` browser download round trip pass. Persistence-status and file-save adapters pass unit tests and mocked browser adapter checks. Real native picker behaviour on Windows 11 and Firefox/WebKit checks are pending.
- Remaining Phase 0 work: rest of the command registry, multi-command gesture transactions, future production migration fixtures, remaining repository durability features, other performance operations and the required spike gaps.

The roadmap blocks Phase 1 until S-01 through S-06 pass or recorded adapter swaps satisfy their gates.

## Resolved specification question

The user chose to add optional `mergeLayers` to font-profile options. Its default is `false`, so existing profiles retain the documented duotone export error. The OTF font-construction spike accepts already filled glyph paths; full font export, including stroke outlining and duotone handling, remains pending.
